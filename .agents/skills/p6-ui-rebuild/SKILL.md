# P6 UI 结构级重构

## 必须先读

1. 阅读 [UI 强制规范](references/ui-standards.md)。
2. 阅读本次目标参考图，确认画板尺寸、区块顺序、比例和信息密度。
3. 阅读当前页面、路由、共享组件、API service 和对应后端接口。
4. 仅在必要时查阅：
   - `docs/智能运营分析项目_UI优化参考图与当前功能差异分析说明文档_v20260621.docx`
   - `docs/智能运营分析项目_P6_UI与功能排版优化落地方案_Codex版_v20260622.docx`

未完成以上步骤，不得开始编辑页面。

## 执行流程

### 1. 建立事实基线

- 确认目标页面路由、当前 DOM/layout、真实 API、加载态、空态和错误态。
- 调用或检查真实接口，确认字段、单位、时间范围和空数据表现。
- 列出拟修改文件、共享组件复用点、缺失接口及风险。

### 2. 选择改造方式

- 用户要求“重做、重构替换、1:1 复刻”时，整页重写业务页面 DOM/layout。
- 删除旧页面布局依赖时，只移除明确的旧代码，不批量删除文件或目录。
- 保留 React 18、TypeScript、Vite、Ant Design、ECharts、FastAPI、PostgreSQL、Redis/Celery 技术栈。
- 优先复用项目设计 token、AppShell、全局导航及统一基础组件；不得复用与参考图冲突的旧排版逻辑。

### 3. 实现页面

- 以参考图为视觉和结构主准绳，以真实项目 API 和业务能力为功能边界。
- 使用 Grid/Flex 建立稳定结构，避免依赖绝对定位拼图。
- 无 API 时先补后端接口；禁止用 mock、demo、硬编码业务记录替代。
- 正常页面不展示“真实数据、派生数据、API 来源”等技术标签；数据失败时展示明确错误或空态。
- 对内容过多的表格、洞察栏和子卡片使用内部滚动，不用页面级滚动掩盖排版问题。

### 4. 强制验收

依次完成：

1. TypeScript 检查。
2. `npm build`。
3. 浏览器检查目标画板及常用宽度。
4. 检查横向滚动、页面级纵向滚动、裁切、重叠、空白、控制台错误。
5. 生成实现截图并与参考图对照。
6. 说明修改文件、复用/新增接口、测试结果、风险和未完成项。
7. 按阶段建立独立 git commit；不得夹带无关文件。

任一强制项失败时，不得宣称完成。
