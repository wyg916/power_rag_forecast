# P6 UI 结构级重构

## 必须先读

1. 阅读 `docs/P6_UI优化前必读统一SKILL.md` 的通用规则和本次页面对应章节。
2. 阅读 [UI 强制规范](references/ui-standards.md)。
3. 阅读本次目标参考图和用户最新标注截图，确认画板尺寸、区块顺序、比例和信息密度。
4. 阅读当前页面、路由、共享组件、API service 和对应后端接口。
5. 按页面关键词定向查阅：
   - `docs/智能运营分析项目_UI优化参考图与当前功能差异分析说明文档_v20260621.docx`
   - `docs/智能运营分析项目_P6_UI与功能排版优化落地方案_Codex版_v20260622.docx`

未完成以上步骤，不得开始编辑页面。

`docs/P6_UI优化前必读统一SKILL_打包版/SKILL.md` 是总规范的相同内容分发备份。确认两者内容相同时，不重复读取。

## 规则优先级

出现冲突时依次遵循：

1. 用户在当前任务中的最新明确要求。
2. 数据真实性、安全性、只读 SQL、RAG 降级和禁止伪造能力等硬边界。
3. 根目录 `AGENTS.md`。
4. 本执行技能。
5. 统一总规范与 `references/ui-standards.md`。
6. 历史 Word 方案和较早截图说明。

展示层标签可按用户最新要求隐藏，但任何 mock、fallback、派生结果或未部署能力都不得冒充真实生产能力。

## 执行流程

### 1. 建立事实基线

- 确认目标页面路由、当前 DOM/layout、真实 API、加载态、空态和错误态。
- 调用或检查真实接口，确认字段、单位、时间范围和空数据表现。
- 列出拟修改文件、共享组件复用点、缺失接口及风险。

### 2. 选择改造方式

- 用户要求“重做、重构替换、1:1 复刻”时，整页重写业务页面 DOM/layout。
- 删除旧页面布局依赖时，只移除明确的旧代码，不批量删除文件或目录。
- 保留 React 18、TypeScript、Vite、Ant Design、ECharts、FastAPI、PostgreSQL、Redis/Celery 技术栈。
- 优先复用项目设计 token、AppShell、全局导航及统一基础组件；不得复用与参考图冲突的旧排版逻辑。

### 3. 实现页面

- 以参考图为视觉和结构主准绳，以真实项目 API 和业务能力为功能边界。
- 使用 Grid/Flex 建立稳定结构，避免依赖绝对定位拼图。
- 无 API 时先补后端接口；禁止用 mock、demo、硬编码业务记录替代。
- 正常页面不展示“真实数据、派生数据、API 来源”等技术标签；数据失败时展示明确错误或空态。
- 对内容过多的表格、洞察栏和子卡片使用内部滚动，不用页面级滚动掩盖排版问题。


### 3.1 布局、边界与响应式硬性要求

- 页面在浏览器打开状态下应尽量铺满可视区域，主体内容充分利用屏幕宽度和高度；同时四周必须保留统一、安全、适度的外边距，不得出现内容贴边、硬截断或边界不整齐的问题。
- 页面整体容器、顶部栏、侧边栏、主内容区、卡片区和图表区必须形成清晰的版心关系；外边界、圆角、阴影和背景留白应统一，避免出现“截图被切掉”“边缘生硬”“内容顶到屏幕边”的观感。
- 各子板块、卡片、图表、表格、筛选栏、操作按钮之间必须保持统一等距间隔。优先使用统一 spacing token 或固定 Grid/Flex gap，不得通过随意 margin 拼接，不得出现组件重叠、错位、压线、间距忽大忽小。
- 每个组件内部内容必须跟随所在子块尺寸自适应：标题、指标、图表、表格、标签、按钮应在容器内完整、有序展示；禁止文本、图表、按钮溢出卡片边界。
- 内容较多的子卡片、表格、日志、洞察列表、任务列表、AI 建议区，应优先设置卡片内部滚动或折叠/分页/查看更多机制；不得通过撑爆页面、遮挡相邻模块或制造横向滚动来解决。
- 顶部区域不得浪费大块空白。若参考图顶部有可利用空间，应合理承载项目选择、时间、地区、模型版本、筛选条件、主要操作按钮、状态标识等内容，使顶部栏兼具信息承载和操作入口。
- 在非全屏、窗口缩放、常见笔记本分辨率和浏览器缩放场景下，界面必须能够自适应调整，保持完整、整齐、可读；必要时采用响应式换行、列数调整、卡片堆叠、内部滚动，而不是裁切或遮挡。
- 桌面端页面原则上不得出现横向滚动条；纵向滚动只允许在内容确实超出首屏时出现，且不能掩盖首屏关键布局错乱。
- 图表容器必须监听尺寸变化并自适应重绘；ECharts 等图表不得因容器变化出现挤压、截断、图例覆盖、坐标轴文字重叠。
- 实现完成后必须用目标参考图尺寸、全屏窗口、非全屏窗口和至少一个较窄桌面宽度进行截图检查，重点核对：整体边界、顶部空白利用、板块等距、组件重叠、内容溢出、内部滚动、横向滚动和响应式完整性。

### 4. 强制验收

依次完成：

1. TypeScript 检查。
2. `npm build`。
3. 浏览器检查目标画板及常用宽度。
4. 检查横向滚动、页面级纵向滚动、裁切、重叠、空白、顶部空间浪费、边界贴边、间距不统一、组件内容溢出和控制台错误。
5. 分别在全屏、非全屏和常用桌面宽度生成实现截图，并与参考图对照。
6. 说明修改文件、复用/新增接口、测试结果、风险和未完成项。
7. 按阶段建立独立 git commit；不得夹带无关文件。

任一强制项失败时，不得宣称完成。
