# P6 UI 优化强制规范

## 1. 核心目标

- 页面优化属于“UI 结构级重构”，不是局部美化或微调。
- 用户提供参考图时，参考图是结构、顺序、比例、间距和信息密度的第一视觉标准。
- 当前仓库、真实接口和真实业务能力是数据与功能边界；不得为了复刻截图伪造能力。
- 目标是企业级、生产级、可信的售电运营与预测分析后台，不是官网、深色大屏或低信息密度 Demo。

## 2. 技术与复用边界

- 保持 React 18 + TypeScript + Vite + Ant Design + ECharts + FastAPI + PostgreSQL + Redis/Celery。
- 优先复用 `BasicLayout`、`HeaderBar`、`Sidebar`、`PageContainer`、`MetricCard`、`SectionCard`、`TableCard`、`DetailDrawer` 及现有 API service。
- 新的领域组件放入 `frontend/src/components/<domain>/`，不得在页面内堆积大段重复结构。
- 共享组件可扩展，但不得为一个页面破坏其他路由。
- 不允许放宽只读 SQL 安全、隐藏 RAG 降级、伪造中间件、状态机或业务完成状态。

## 3. 页面结构

默认信息层级：

1. PageHeader
2. Filter / Context Bar
3. KPI Summary
4. Primary Visualization
5. Insight / Explanation
6. Detail Table
7. Action / Operation
8. 可选右侧 AI / Strategy / Risk Sidebar

当参考图使用不同组合时，保持其模块顺序和比例，但仍需具备清晰的信息层级。

## 4. 全局框架

### 左侧导航

- 顶部：Logo、`智能运营分析`、`售电交易决策平台`。
- 一级：首页。
- 业务中心：数据中心、预测中心、策略中心、报告中心。
- 智能应用：AI 助手、知识库。
- 运营管理：模型中心、任务中心、系统设置。
- 显示当前板块卡片和“收起菜单”。
- 当前项使用浅绿色背景、绿色文字与图标。

### 顶部栏

- 高度 56-64px，白色背景，底部细边框。
- 只展示真实可用的项目、数据时间、区域、模型版本、用户及全局操作。
- 通知、帮助、刷新等功能无效时必须修复或移除，不得保留假入口。

## 5. 视觉系统

- 页面背景：浅灰蓝。
- 卡片：白色、10-12px 圆角、1px 浅灰蓝边框、轻阴影。
- 间距：以 16/24px 网格为主，小型紧凑区域可使用 8/12px。
- 字体：Inter / PingFang SC / Microsoft YaHei / system font。
- 页面标题 22-24px，卡片标题 15-16px，表格正文 13-14px，辅助说明 12-13px。
- 状态色：正常/成功/优为绿色；中风险/波动为橙色；高风险/异常为红色；信息/运行中/模型说明为蓝色。
- 禁止装饰性渐变球、无关插画、过度圆角、巨型标题和一味放大的留白。

## 6. 布局与响应式

- 设计基准为 1672 x 941，同时检查 1366、1440、1920 常见桌面宽度。
- 禁止页面横向滚动、右侧裁切、卡片重叠和文本溢出。
- 用户要求单屏完整显示时，页面主体不得上下滚动；通过压缩冗余高度、合理分配主图区和内部滚动实现。
- 内容过多时，仅允许表格、洞察、日志、任务列表等子板块内部滚动。
- 卡片上下边缘、同层标题线和底部必须对齐；不得留下大片无业务意义空白。
- 主要内容使用 Grid + Flex，自适应列宽；禁止用大量 absolute 拼接布局。
- 窄窗口应重排或压缩，不得简单隐藏关键业务信息。

## 7. 数据真实性

- 禁止 mock、demo、随机数和硬编码业务结果。
- KPI、图表、表格和状态必须来自后端 API 或由真实 API 字段透明计算。
- 缺少接口时先新增后端接口，前端不得填充假数据。
- API 失败、字段缺失或无数据时展示 Loading / Empty / Error 状态，不得回退到伪造记录。
- 正常页面不堆叠“真实数据、派生数据、data source、API 名称”等技术标签；仅在用户明确要求或诊断页面中显示。
- 派生指标必须可追溯、单位正确、算法可解释；不能把套利空间、预测值等描述成已实现收益。
- 不向用户直接暴露 SQL、堆栈或数据库异常全文。

## 8. 组件内容要求

### KPI

- 包含图标、指标名、主数值、单位、变化或时间信息。
- 参考图有趋势线时使用真实序列绘制；无真实序列时不伪造趋势线。
- 状态和颜色与指标语义一致，卡片不得空洞。

### 图表

- 使用 ECharts。
- 具备图例、坐标轴、单位、tooltip 和必要的业务标注。
- 风险窗口、峰谷区间、置信区间和关键点仅在真实数据支持时展示。
- resize 后必须正确重绘，禁止空白 canvas 或裁切。

### 表格

- 紧凑、可读，浅色表头，包含状态标签、操作入口和分页或内部滚动。
- 列宽、数字对齐、单位和时间格式一致。
- 操作入口必须可用；不可用功能应显示待接入态或移除。

### 洞察与任务

- AI 建议、策略解释、风险提示必须来自真实接口或明确可追溯规则。
- 子板块充分利用高度，内容不能只占顶部而下方大片留白。
- 任务失败应提供可用的重试、日志或明确待接入状态。

## 9. 状态与交互

- 所有页面具备 LoadingState、EmptyState、ErrorState。
- 刷新、导出、筛选、分页、详情、重试和导航必须实际工作。
- 未部署的审核、发布、人工复核、模型生命周期等状态机只能展示“待接入”，不得伪造流程完成。
- 弹窗、抽屉和下拉层不得超出视口或遮挡核心操作。

## 10. 验收清单

- [ ] 与参考图结构一致度达到 95% 以上。
- [ ] 无旧页面 DOM/layout 残留。
- [ ] 无 mock/demo/随机业务数据。
- [ ] KPI、图表、表格使用真实 API。
- [ ] 页面无横向滚动和右侧裁切。
- [ ] 单屏要求满足；长内容改为子板块内部滚动。
- [ ] 主要卡片边缘对齐，无大片无效空白。
- [ ] 所有可见按钮可用或已移除/标记待接入。
- [ ] Loading、Empty、Error 状态完整。
- [ ] TypeScript 检查通过。
- [ ] `npm build` 通过。
- [ ] 目标尺寸浏览器截图通过视觉对照。
- [ ] 浏览器控制台无错误和警告。
- [ ] 已列出修改文件、接口、测试、风险与未完成项。
- [ ] 已建立独立 git commit，未夹带无关文件。

## 11. 每次任务的最小交付

1. 修改文件清单。
2. 页面截图或截图检查点。
3. 复用/新增接口说明。
4. 构建和相关测试结果。
5. 风险与未完成项。
6. 独立 git commit。
