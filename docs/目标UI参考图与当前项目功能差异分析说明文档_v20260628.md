# 《目标UI参考图与当前项目功能差异分析说明文档》

生成日期：2026-06-28  
项目：AI 售电交易决策平台 / 智能运营分析项目  
分析范围：目标 UI 参考图、当前前端代码、后端 API 路由、项目说明文档、P6 UI 前置规范。  
执行边界：本轮仅做分析文档，不修改业务代码、不修改接口、不改数据库、不改权限逻辑。

## 1. 项目当前UI现状总览

当前项目已经具备完整 Web 产品骨架：`React 18 + TypeScript + Vite + Ant Design + ECharts` 前端，`FastAPI + PostgreSQL + Redis/Celery` 后端，页面按 `dashboard / data / forecast / strategy / assistant / report / model / knowledge / task / settings` 十个一级模块组织。

前端入口为 `frontend/src/app/App.tsx`，通过 `BasicLayout`、`HeaderBar`、`Sidebar`、`PageContainer` 承载所有业务页面。路由采用 Hash 模式，`frontend/src/app/router.tsx` 已配置数据中心 2 个子页、预测中心 3 个子页、策略中心 4 个子入口，以及 AI、报告、模型、知识库、任务、设置等子页。

当前已经存在一批 P6 通用组件：`MetricCard`、`SectionCard`、`TableCard`、`ChartCard`、`DetailDrawer`、`FilterBar`、`PageTabs`、`DataStateBanner`、`DataSourceTag`、`StatusTag`、`ActionButton`、`GaugeChart`、`PriceCurveChart`、`Sparkline`。但仍存在三个主要问题：

1. 部分页面已经有业务功能，但 UI 表达方式还没有完全达到目标图的信息密度、三栏布局、首屏铺满和企业级 SaaS 质感。
2. 部分页面仍有 mock/fallback 或前端派生字段，例如报告、模型、任务、AI 助手、系统设置在接口失败或空返回时会进入本地兜底；预测置信区间、策略收益、SOC、部分历史对比指标属于派生或待真实回填。
3. 全局布局与页面局部布局仍存在多阶段改造痕迹，常规浏览器窗口下可能出现空白浪费、卡片底部不齐、局部滚动不稳定、右侧面板裁切等问题。

## 2. 目标UI整体风格总结

目标 UI 图属于统一的企业级 SaaS 后台控制台风格：

- 左侧导航：白色侧栏、绿色选中态、分组说明、当前板块卡片、底部收起菜单。
- 顶部栏：56-64px 高，项目、数据时间、区域、模型版本、状态标签、通知/帮助/刷新、用户信息。
- 页面背景：浅灰蓝，内容区左右 20-24px。
- 卡片：白底、10-12px 圆角、细边框、轻阴影。
- 信息密度：KPI + 图表 + 右侧洞察 + 底部表格/状态卡，尽量一屏完整展示。
- 业务表达：不是普通折线图或表格，而是带风险窗口、峰谷标注、AI 建议、数据依据、审核流、执行状态的业务化组件。
- 响应式：普通窗口和全屏均要铺满可视区，禁止大面积空白、横向滚动、内容裁切。

## 3. 全局Layout差异分析

当前 `BasicLayout/HeaderBar/Sidebar/PageContainer` 已经具备目标框架雏形，且导航分组基本符合目标目录结构。但与目标图相比仍有差距：

- Header：当前顶部栏已有项目、搜索、数据时间、区域、模型版本、只读 SQL、帮助、刷新、用户区；但部分交互曾出现不可用问题，后续要统一为“有效则保留，无效则移除或进入待接入态”。
- Sidebar：当前已按首页、业务中心、智能应用、运营管理分组，但需继续保持 204-220px 宽度、选中态、当前板块卡片与目标图一致。
- PageHeader：部分页面隐藏全局 PageContainer header，自行实现页面标题，这是正确方向；但每个页面的标题、筛选条、操作区位置要严格按参考图统一。
- 可视高度：目标页面需要常规窗口内完整铺满，页面整体尽量不出现主窗口纵向滚动；内容过多时改为子卡片内部滚动。
- 数据状态：当前 `DataStateBanner/DataSourceTag` 可显式标注 mock/fallback/derived；但用户已提出普通业务页不希望到处显示“真实数据/派生数据”标签。因此后续策略应是：正常真实数据隐藏技术标签；mock/fallback/派生/待接入必须醒目标注。

## 4. 全局Design System优化建议

建议保留并强化现有设计系统，而不是另起一套：

- Design Tokens：统一颜色、字号、间距、圆角、阴影、状态色，集中在 `frontend/src/theme/variables.css` 与 `themeConfig.ts`。
- 基础组件：继续复用 `MetricCard`、`SectionCard`、`TableCard`、`ChartCard`、`FilterBar`、`PageTabs`、`DetailDrawer`。
- 新增组件方向：`ChartPanel`、`InsightPanel`、`RiskCard`、`ActionCard`、`ModelMetricCard`、`DataHealthCard`、`OperationTimeline`、`AuditPanel`。
- 图表规范：所有 ECharts 图表必须包含图例、业务标注、风险窗口、单位、空态与 loading。
- 表格规范：紧凑表头、状态标签、操作链接、分页、局部滚动，避免主页面被表格撑高。
- 空态规范：空态需解释真实原因，例如“接口返回为空”“待接入”“权限不足”“RAG 降级”，不得用虚假数据填充。

## 5. 各页面逐页分析

### 5.1 首页 / 总览驾驶舱

1. 页面在项目整体中的定位  
首页是系统入口和统一驾驶舱，聚合今日供需风险、预测、策略、报告、任务、数据健康和 AI 建议，帮助运营人员快速判断当天是否需要采取交易或复核动作。

2. 业务目标  
快速回答“今天是否有高价风险、预测是否可信、策略是否已生成、报告是否待审、任务是否异常、数据是否健康、AI 有何建议”。

3. 目标 UI 图中的功能模块  
顶部全局 Header、左侧导航、首页标题与操作按钮、KPI 指标卡、24h 供需风险主图、右侧 AI 建议摘要、策略执行摘要、任务提醒、快捷入口、底部关键预测指标、模型状态、数据健康。

4. 当前项目已实现的功能  
`DashboardPage.tsx` 已重构为首页驾驶舱，拆分到 `components/dashboard/*`。`homeDashboardApi.ts` 聚合 `/api/dashboard/kpi`、`/api/risk/summary`、`/api/strategy/today`、`/api/forecast/24h`、`/api/task/recent`。已有 KPI、主图、AI/策略/任务侧栏、数据健康、快捷入口、任务日志查看。

5. 当前项目与目标 UI 的差异  
功能覆盖度较高，但仍需持续验证一屏完整显示、卡片下边对齐、主图高度和右侧卡片内部滚动。部分指标如策略收益、风险指数、数据健康若来自派生或接口异常，必须保持明确边界，不能被用户误认为真实生产回填。

6. 后续优化建议  
保持旧 Home 布局彻底移除；继续用 `components/dashboard` 维护；主图、辅助卡和右侧栏按 1672x941 与常规窗口双尺寸验收；普通真实数据状态不展示技术标签，异常/派生/待接入才展示。

7. Figma复刻建议  
画布 1672x941；左侧 216px，主内容按 6 KPI、主图 68%、右栏 32%、底部 3 卡布局；重点复刻 KPI 行、24h 主图、右侧三段卡和底部对齐。

8. Codex工程落地建议  
主要文件：`DashboardPage.tsx`、`components/dashboard/*`、`styles.css`、`homeDashboardApi.ts`。阶段：先稳定首屏网格，再做卡片内部滚动，最后做截图验收。

### 5.2 数据中心

1. 页面在项目整体中的定位  
数据中心是数据可信入口，负责展示数据接入、同步、质量、目录、表结构和异常状态，为预测、策略、报告和 AI 提供可信数据基础。

2. 业务目标  
让用户知道数据是否齐全、是否新鲜、质量是否达标、哪些表异常、数据目录和字段含义是什么，以及能否安全查询。

3. 目标 UI 图中的功能模块  
数据总览主页面：筛选栏、数据源数量、同步任务、异常表、完整率、昨日更新量、数据接入流程、同步记录、健康摘要、快捷操作、告警提醒。  
数据质量/目录组合页：缺失率、重复率、新鲜度、校验通过率、异常表数、质量趋势、异常明细、目录卡片、选中表字段预览、数据源状态条。

4. 当前项目已实现的功能  
`DataCenterPage.tsx` 已根据 `activeSubKey` 切换 `data-overview` 与 `data-quality`。`DataCenterDesign.tsx` 已提供 `DataOverviewMetrics`、`DataFlowPanel`、`DataHealthOverview`、`SyncRecordsTable`、`QualityMetrics`、`QualityMonitor`、`ExceptionTable`、`CatalogPanel`、`SourceStatusBar`。`dataApi.ts` 聚合 `/api/data/status`、`/api/data/quality`、`/api/data/tables`、`/api/data/import-export-records`、`/api/data/catalog`、`/api/data/freshness`，不使用 mock fallback。

5. 当前项目与目标 UI 的差异  
两个目标页面均有实现入口，但需要确认导航能直达“数据质量 / 数据目录组合页”。数据总览当前在某些窗口下仍可能出现底部空白或下方卡片不齐。质量/目录页的字段详情、血缘关系、目录管理和批量处理需要进一步贴近目标图。

6. 后续优化建议  
确保 `data-overview`、`data-quality` 两个子页在 Sidebar 当前板块、URL、Tabs/子导航中明确可达；数据总览把筛选/操作上移利用标题空白，主内容一屏铺满；质量页加强右侧目录卡片和选中表字段详情。

7. Figma复刻建议  
数据总览采用 5 KPI + 左流程右健康 + 左同步表右快捷/告警。质量页采用 5 KPI + 左质量监控/异常表 + 右目录/表详情 + 底部数据源状态。

8. Codex工程落地建议  
主要文件：`DataCenterPage.tsx`、`DataCenterDesign.tsx`、`dataApi.ts`、`styles.css`。优先修正子页接入和一屏高度，再优化质量/目录详情组件。

### 5.3 预测中心

1. 页面在项目整体中的定位  
预测中心是电价预测与模型可信解释入口，承担未来 24 小时预测、历史/批次对比、峰谷分析与模型评估。

2. 业务目标  
帮助用户识别高价风险、低价采购窗口、预测可信度、峰谷价差、模型表现和历史变化原因。

3. 目标 UI 图中的功能模块  
24h 页：筛选栏、5 KPI、预测曲线、置信区间、低价窗口、高风险时段、峰值标注、右侧策略洞察、预测明细、模型状态、峰谷小结、数据健康。  
历史对比页：Tabs、筛选栏、6 KPI、三线对比图、关键变化洞察、对比明细、变化结论、可解释性、数据健康。  
峰谷/模型评估页：Tabs、筛选栏、6 KPI、价差仪表盘、峰谷策略解释、P2 模型评估卡、Baseline 对比、训练与回测状态。

4. 当前项目已实现的功能  
`ForecastCenterPage.tsx` 已通过 `activeSubKey` 切换 `forecast-24h`、`forecast-history`、`forecast-model`。`ForecastDesign.tsx` 已提供 `ForecastMetricCards`、`ForecastChartCard`、`StrategyInsightPanel`、`ForecastDetailTable`、`ForecastSummaryCards`、`ComparisonChartCard`、`ComparisonInsightPanel`、`ComparisonDetailTable`、`PeakAndModelTop`、`ModelEvaluationCards`、`BaselineAndTraining`。`forecastApi.ts` 接入 `/api/forecast/24h`、`/api/forecast/latest`、`/api/prediction/latest`、`/api/prediction/detail`、`/api/market/history`、`/api/risk/summary`、`/api/strategy/today`、`/api/models/*`。

5. 当前项目与目标 UI 的差异  
三页工程入口已存在，但历史对比和模型评估是否达到目标图 95% 仍需截图验收。置信区间、预测可信度、历史对比、峰谷价差存在前端派生逻辑，若后端无直接结果，需要在 UI 中保留“派生/待接入”边界。24h 页面当前反馈过主图显示不全、底部空白、指标卡曲线真实性问题，需要用真实 series 派生 sparkline 并避免裁切。

6. 后续优化建议  
明确三子页导航；24h 页把主图高度控制在一屏内，表格内部滚动；历史页必须确认 `/api/market/history` 返回真实历史/上一批次，否则不能包装成真实对比；模型页优先复用 P2 API，缺失状态用待接入而非假数据。

7. Figma复刻建议  
三页统一 1672x941，左栏 216px，内容区 24px。24h 强调主图和右侧策略洞察；历史强调三线图和变化原因；模型页强调价差仪表盘、P2 卡片和 baseline 表。

8. Codex工程落地建议  
主要文件：`ForecastCenterPage.tsx`、`ForecastDesign.tsx`、`forecastApi.ts`、`components/charts/*`。分三阶段：24h 稳定一屏、接入历史对比、完善模型评估。

### 5.4 策略中心

1. 页面在项目整体中的定位  
策略中心是预测结果向交易动作转化的决策入口，包含策略总览、低价窗口/储能策略、人工复核。

2. 业务目标  
把高价风险、低价采购窗口、储能充放电建议、收益估算、风险等级、人工复核和执行清单串成闭环。

3. 目标 UI 图中的功能模块  
总览：策略日期筛选、策略结论、高价风险、低价窗口、预计收益、人工复核数、策略时间轴、策略建议说明、关键操作建议、风险来源分布、执行状态、收益对比。  
低价/储能：低价窗口表、SOC 趋势、充放电功率、收益预估、时段详情、执行条件、加入执行清单。  
人工复核：复核 KPI、复核列表、批量通过/驳回/标记、右侧复核详情、AI 风险摘要、证据链、相关时段数据、备注和处理意见。

4. 当前项目已实现的功能  
`StrategyCenterPage.tsx` 已根据 `strategy-high`、`strategy-low/strategy-storage`、`strategy-review` 切换 `overview/storage/review`。`StrategyDesign.tsx` 已有 `StrategyOverviewMain`、`StrategyOverviewBottom`、`StorageWorkspace`、`ReviewWorkspace`。`strategyApi.ts` 接入 `/api/strategy/today`、`/api/strategy/latest`、`/api/anomaly/latest`、`/api/strategy/config`、`/api/forecast/24h`，复核保存走 `/api/strategy/reviews`。

5. 当前项目与目标 UI 的差异  
策略总览、储能、复核已具备页面结构，但真实执行清单、真实 SOC、实际收益回填、完整复核状态机仍不足。当前 SOC 明确为参数化估算，不能当作真实储能设备状态。低价窗口和储能策略目前合并为同一模式，目标图可接受，但导航文案要清晰。

6. 后续优化建议  
总览页保持目标图的时间轴和策略建议结构；储能页把 SOC 标注为参数化或接入真实设备数据；复核页补状态流转、SLA、证据链和批量操作真实后端支撑。

7. Figma复刻建议  
三页统一策略中心风格。总览用主图 + 右说明 + 底部四卡；储能用左时段、中图表、右详情；复核用左列表、右详情固定栏。

8. Codex工程落地建议  
主要文件：`StrategyCenterPage.tsx`、`StrategyDesign.tsx`、`strategyApi.ts`。阶段：先总览高保真，再储能/SOC，最后人工复核状态机。

### 5.5 AI助手

1. 页面在项目整体中的定位  
AI 助手是面向运营人员的问答与决策解释入口，连接预测、策略、数据、报告和知识库证据。

2. 业务目标  
把用户问题转化为带数据依据、知识引用、关键指标和建议动作的回答，并保留工具调用、Trace 和反馈链路。

3. 目标 UI 图中的功能模块  
左侧会话列表/常用问题，中间问答主窗口，右侧数据依据、关键指标摘要、知识引用、策略建议、风险提示，底部输入区，开发者 Trace 可选。

4. 当前项目已实现的功能  
`AssistantPage.tsx` 已实现会话列表、常用问题、聊天回答、模型 provider 选择、反馈、工具调用、Trace、数据依据、关键指标摘要、知识与策略建议。`assistantApi.ts` 接入 `/api/ai/chat/sessions`、`/api/ai/chat`，并在失败时有 mock fallback。后端支持 `/api/ai/chat`、`/api/ai/agent/analyze`、`/api/ai/traces`、`/api/ai/feedback`。

5. 当前项目与目标 UI 的差异  
功能较完整，但部分调试信息对普通用户过重；如果接口失败会进入离线兜底，必须醒目标注。目标图强调“决策助手 + 证据栏 + 指标摘要 + 建议动作”，当前仍需压缩开发者内容，增强业务回答结构。

6. 后续优化建议  
默认隐藏 Trace 和工具日志，仅 developer/admin 可见；右侧证据栏固定；回答区支持结构化卡片；RAG/LLM 降级必须明显提示；常用问题要围绕售电业务场景。

7. Figma复刻建议  
三栏布局：会话 260-300px，中间自适应，右侧 360-420px；输入区固定在中间底部；证据卡可内部滚动。

8. Codex工程落地建议  
主要文件：`AssistantPage.tsx`、`assistantApi.ts`、`components/common/TracePanel.tsx`。阶段：布局重构、回答结构化、权限/降级提示优化。

### 5.6 报告中心

1. 页面在项目整体中的定位  
报告中心是经营分析结果的审核、发布和归档闭环入口。

2. 业务目标  
支持日报/周报/专题报告查看、生成、预览、审核通过/驳回、发布归档和审核记录追踪。

3. 目标 UI 图中的功能模块  
报告列表、报告预览、报告摘要、审核操作、发布记录、归档时间线、版本信息、下载、重新生成、详情抽屉。

4. 当前项目已实现的功能

## 8. UI差异优先级排序

P0：全局 Layout、Header、Sidebar、Design Tokens、PageContainer、状态/空态。  
P1：首页、AI助手、预测中心。  
P2：数据中心、策略中心、报告中心。  
P3：模型中心、知识库、任务中心、系统设置。

优先处理原因：

- P0 决定所有页面一致性，不先统一会造成重复返工。
- P1 是用户日常最高频入口，直接影响产品第一印象和业务决策。
- P2 承接数据可信、策略闭环、报告闭环，是业务落地关键。
- P3 偏后台管理，可在主业务页面稳定后统一治理。

## 11. 风险点和注意事项

- 禁止 mock/fallback 冒充真实生产数据。
- 禁止隐藏 RAG 降级、LLM 不可用、接口异常。
- 禁止放宽只读 SQL 安全校验。
- 未部署中间件不得在系统设置里显示为已接入能力。
- 策略收益、SOC、执行状态、历史对比必须区分真实回填、预测派生和待接入。
- 页面整体要适配普通浏览器窗口，不能只在全屏下正常。
- 详情过多时应使用子卡片内部滚动，不应拉长主页面。
- 每次 UI 优化前必须读取 `.agents/skills/p6-ui-rebuild/SKILL.md`、`docs/P6_UI优化前必读统一SKILL.md`、`references/ui-standards.md`，并结合本次目标图和当前代码再实施。
