# 智能运营分析项目知识契约（PHASE5-A）

本文件汇总已经由项目工程规则、阶段三验收和当前源代码确认的字段、指标、市场、模型与来源契约。它只描述当前本地开发/演示基线，不代表生产部署、自动交易能力或未来实时数据。

## 字段与系统事实契约

`run_id` 标识一次可追踪的预测批次，用于关联同一批预测运行、逐时预测结果及其来源元数据。Web、API 和 AI 必须共享同一个 `run_id`，并共享 `source_type`、`generated_at`、模型版本、特征版本等来源信息，不能各自生成互不相关的批次。

`predicted_price` 表示模型预测电价，当前项目字段字典中的单位是 `USD/MWh`。它是模型输出，不是成交价或交易指令。`generated_at` 表示数据或知识的生成时间，`effective_at` 表示规则或知识开始生效的时间；二者含义不同。

`source_type` 用于区分 `real`、`historical`、`demo`、`seed`、`fallback`、`derived` 和 `unavailable`。`real` 表示有当前真实来源契约支持的事实；`historical` 表示历史或已过期证据；`demo`、`seed` 和 `fallback` 不能冒充 real；`derived` 是从证据推导的解释；无可信证据时必须返回 `unavailable`。

PostgreSQL 中的成功预测运行与预测结果是预测事实源；`model_registry` 是模型事实源，`model_versions` 只保留 legacy 兼容用途。GET 和其他查询接口必须只读，不能自动 seed、生成正式事实、激活模型或补写 Embedding。seed、导入、Embedding、模型验证和激活都必须通过显式命令或写操作执行。

Candidate 模型不能自动晋升为 Active。Candidate 必须完成准入验证，仍需人工确认后才能显式激活；验证通过不等于自动切换生产模型。当前项目是可稳定本地运行的开发/演示基线，不是生产交易系统。

## 预测指标与模型解释契约

MAE 是平均绝对误差，即各样本预测误差绝对值的平均。MAE 越小通常表示平均误差越低，它不是百分比指标。RMSE 是均方根误差，对较大的误差给予更高权重，因此通常比 MAE 对尖峰或异常误差更敏感；二者不要求数值相同。

峰谷价差按所选时段最高价减最低价计算，反映时段内价格波动空间，但不能直接等同于可实现收益。预测区间覆盖率必须与区间宽度一起解释：仅提高区间宽度也可能提高覆盖率，因此覆盖率高不代表点预测一定更准确。

模型输入必须严格满足特征契约，包括列名、列集合、顺序、类型、时区和 schema hash。缺列、额外列、顺序变化或类型不一致时必须 fail-closed，禁止静默补零。模型 artifact 的 manifest 记录模型身份、artifact hash、模型版本、特征版本、schema hash、依赖和指标等外部元数据，用于加载前校验；manifest 本身不是模型二进制。

预测模型输出只用于分析和辅助决策，不能直接作为交易指令。交易还必须结合合同敞口、风险限制、实时市场证据和人工复核；本项目不执行自动下单。

晚高峰预测误差可能同时受到负荷变化、温度等天气扰动、新能源出力、供应或输电约束以及尖峰价格波动影响，不能只归因于算法。尖峰概率高表示需要重点监控风险，不代表价格一定暴涨。

天气预测偏差会先影响负荷或新能源出力等输入，再传导到电价预测。发现近期误差变大时，应检查数据质量、样本量、持续退化、分时段误差和市场结构变化；不能依据单次异常自动重训、自动激活。重训和晋升均需足够样本、准入验证和人工确认。

## 电价市场基础契约

PJM 市场的 LMP 是 Locational Marginal Price，即节点边际电价。典型 LMP 由能源、输电拥塞和边际损耗等分量构成，不只是燃料成本。项目中的 DOM 指 PJM 的 Dominion 区域或相关节点背景，不是中国省级电网代码。

日前市场在实际运行日前完成计划和价格出清；实时市场用于处理实际运行与日前计划之间的偏差、约束和实时平衡。两者的时间尺度与结算作用不同。

峰谷价差按所选时段最高价减最低价计算，反映时段内价格波动空间，但不能直接等同于可实现收益。

负电价可能由低负荷与供给过剩、新能源集中出力、机组启停或最小出力约束、输电拥塞和补贴激励等因素共同造成。负的批发市场电价不等于终端用户一定免费用电。

## 历史、不可用与防幻觉契约

历史或过期文档必须标记为 `historical`，默认不得参与当前 real 查询；只有调用方显式允许 historical 时才能返回，并必须清楚提示它不是当前有效规则。demo 同样默认不得参与 real 查询。

实时事实不可用、指定文档不存在或关键业务约束缺失时，回答必须标记 `unavailable`，不得使用 demo、fallback 或历史值冒充真实数据或当前事实，也不得编造数值、文档、document_id、chunk_id 或 quote。

当系统从未记录明天的准确成交收益时，不能给出保证收益。请求引用不存在的《2027 自动交易保证盈利规则》时必须拒绝虚构引用。缺少储能 SOC、容量和效率时，不能给出精确充放电量。这些问题的正确行为是说明缺少可信证据或关键约束，并返回 unavailable。
